# Trust boundaries

"Untrusted" means the input may be fully attacker-controlled.

| # | Boundary | Trusted side | Untrusted inputs | Attacker capability | AuthN | AuthZ | Data classes | Network restriction | Logging | Failure behavior |
|---|---|---|---|---|---|---|---|---|---|---|
| 1 | Internet → API | API process | All headers, bodies, paths | Anonymous or any valid tenant user | JWT (iss, aud, exp, nbf, signature via JWKS; EdDSA/RS256/ES256 only) | Scopes per route. Tenant only from a signed claim. | Up to RESTRICTED in payloads | TLS at ingress; NetworkPolicy allows the ingress namespace only | Auth failures (reason), grant changes, exports | 401/403/404/422 with no internal detail. DB down returns 503. |
| 2 | Customer → tenant resources | PostgreSQL RLS | Resource identifiers | Guess or enumerate other tenants' IDs | Inherited from 1 | Forced RLS on every tenant table; composite FKs | All | — | — | Cross-tenant reads return 404, indistinguishable from nonexistent |
| 3 | Agent runtime → orchestrator | Worker (lease holder) | Model output | Arbitrary proposals | Worker holds a fencing token | Fenced writes; transition table | — | — | Every model response recorded | `StaleLease` / `IllegalTransition`, nothing written |
| 4 | Agent output → tool gateway | Gateway, registry, OPA | Tool name, arguments | Prompt-injected or malicious proposals | n/a | Registry membership, schema, OPA decision from server-side grants and approvals | Arguments may be RESTRICTED | — | Decision row and chain event before execution | Deny on unknown tool, invalid args, or any policy error |
| 5 | Gateway → MCP server | Gateway | Tool list, descriptions, annotations, schemas, results | Hostile server | Per-server credentials from the platform; caller tokens are never passed through | Admin mapping and schema pinning | Results stored as data | Fresh process per call; minimal environment | Results recorded | Unmapped or changed tools are not registered; errors become `tool.execution_failed` |
| 6 | Worker → host OS | Host | Built-in tool code | Bugs in tool implementations | — | — | — | — | — | Non-root, read-only root filesystem, all capabilities dropped (compose and k8s) |
| 6b | Sandbox → sandbox host | Sandbox host | **Arbitrary code** | Hostile code | — | — | — | `--network none` | Exit code and truncated output | Timeouts, memory/PID/CPU/file limits. A container is not a complete escape barrier. |
| 7 | Worker → private network | Network | Destinations in tool arguments | SSRF, DNS rebinding, redirects | — | Host allowlist in policy, IP checks in `egress.py` | — | Default-deny NetworkPolicy; metadata IP excluded; egress proxy recommended | Denials recorded | Deny |
| 8 | Application → database | PostgreSQL | SQL parameters | SQL injection via inputs | Separate roles (app, dispatcher, owner) | Least-privilege grants; append-only triggers | All | Private subnets, security groups | Postgres logs | Fail closed. API returns 503. |
| 9 | Application → signing service | Signer interface | Checkpoint bodies (application-built) | Compromised app could request signatures | File or secret permission check | Only workers and the API hold the key (dev); KMS/HSM in production (open item) | Private key | — | Key ID recorded per checkpoint | Workers refuse to start without the key |
| 10 | Application → artifact storage | S3 (reference) | Artifact bytes | Tampering | IAM role | Bucket policy; content addressed by digest | Up to RESTRICTED | VPC endpoint | — | Corruption detected by the verifier (`ARTIFACT_CORRUPTED`) |
| 11 | Customer → exported receipts | The verifier's own trust store and anchor | Entire bundle | Forged or tampered bundles, zip bombs, path traversal | n/a | Verifier never trusts bundle-supplied trust data | Payloads optional (digest-only views) | Offline | Structured report | Reject; never partially trust |
| 12 | Dashboard → administrative operations | Next.js server | Form posts | CSRF, XSS | Token in an httpOnly, SameSite=Strict cookie | API scopes (the dashboard has no privileges of its own) | — | CSP, `frame-ancestors 'none'` | API logs | Redirect to login |
| 13 | CI/CD → deployment | Protected release workflow (planned) | PR code, dependencies | Malicious PRs and dependencies | GitHub OIDC (planned) | `permissions: contents: read` | — | — | Workflow logs | Secret, CVE, or lint failure blocks merge |
